The balance endpoint returns your weekly allowance balance, top-up credits, plan cap, and reset schedule. Call it any time to check how many credits you have left. For an overview of allowances and top-up credits, see [Plans and credits](/plans-and-credits).

## Request

```
GET https://api.kyara-intelligence.com/v1/balance
```

```bash curl
curl https://api.kyara-intelligence.com/v1/balance \
  -H "Authorization: Bearer $KYARA_INTELLIGENCE_API_KEY"
```

<ParamField header="Authorization" type="string" required>
  Your Kyara Intelligence API key, formatted as `Bearer YOUR_API_KEY`.
</ParamField>

## Response

A successful request returns a JSON object with your balances, weekly cap, and reset schedule.

```json
{
  "object": "balance",
  "available": true,
  "plan": "lite",
  "balances": {
    "weekly": { "credits": 24500000, "percent": 70 },
    "additional": { "credits": 0 },
    "total": { "credits": 24500000 }
  },
  "caps": { "weekly": { "credits": 35000000 } },
  "refresh": { "cadence": "weekly", "day": "friday", "time": "06:00Z" }
}
```

<ResponseField name="object" type="string">
  Always `"balance"`.
</ResponseField>

<ResponseField name="available" type="boolean">
  `true` while `balances.weekly.credits + balances.additional.credits` is greater than zero. Otherwise, `false`.
</ResponseField>

<ResponseField name="plan" type="string">
  Your current Kyara plan identifier. Spark returns `"lite"`. Ember returns `"premium"`.
</ResponseField>

<ResponseField name="balances" type="object">
  Your remaining credits broken down by type.

  <Expandable title="Balances object">
    <ResponseField name="weekly" type="object">
      Credits remaining in your weekly allowance. Contains `credits` (integer) and `percent` (number). The credit balance can be negative when a completed request goes over the allowance. `percent` is the remaining balance as a percentage of the weekly cap, clamped from 0 to 100.
    </ResponseField>
    <ResponseField name="additional" type="object">
      Purchased top-up credits. Contains `credits` (integer) only. Top-up credits have no plan cap and never go negative.
    </ResponseField>
    <ResponseField name="total" type="object">
      Weekly allowance credits plus top-up credits. Contains `credits` (integer) only. A negative weekly balance reduces this total.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="caps" type="object">
  The weekly credit limit for your plan.

  <Expandable title="Caps object">
    <ResponseField name="weekly" type="object">
      Maximum weekly allowance credits. Contains `credits` (integer).
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="refresh" type="object">
  The global weekly reset schedule. This object contains static schedule configuration, not per-user billing-window state. Every account resets at the same moment.

  <Expandable title="Refresh object">
    <ResponseField name="cadence" type="string">
      Always `"weekly"`.
    </ResponseField>
    <ResponseField name="day" type="string">
      Always `"friday"`.
    </ResponseField>
    <ResponseField name="time" type="string">
      Always `"06:00Z"`, which is 06:00 UTC.
    </ResponseField>
  </Expandable>
</ResponseField>

## Errors

Errors follow the standard OpenAI error format:

- **`401 authentication_error`**: your API key is missing, malformed, or invalid.
- **`500 server_error`**: the key is valid but Kyara hit missing or invalid balance data.

<Note>
  This endpoint never blocks on an empty balance. It always reports the current state and returns `available: false` when credits are exhausted rather than refusing the request. Reading your balance does not trigger a refill.
</Note>
